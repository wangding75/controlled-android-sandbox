## First error and root cause

The first valid Quark hold showed `u4ashmem ... fstat ... EACCES`, followed by native
recursive initialization and Guest abort. A `memfd_create` admission attempt was kept as
the first failed fix and reverted after targeted regression. Device `readelf` then proved
that `libwebviewuc.so` imports both `fstat` and `fstat64`; the `fstat64` target was added,
but the targeted rerun still failed because Android 16 public `/dev/ashmem<uuid>`
descriptors can arrive before CAS ledger registration.

The final narrow fix adds `fstat64` to the same CAS PLT/replacement path and admits only an
unregistered FD whose trusted `/proc/self/fd/<n>` target is exactly `/dev/ashmem` or one
kernel-named ashmem instance. HostInternal, Broker, stale-revision, and all other unknown
FDs remain fail-closed. No NBB/VA Service/Provider route or Quark-specific branch changed.
