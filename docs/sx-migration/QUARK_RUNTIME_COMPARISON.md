# Quark Runtime Comparison

Date: 2026-08-11  
Device: SX MuMu API32, ADB serial `127.0.0.1:16384`  
Guest: `com.quark.browser`

This comparison follows the T52 rule of collecting evidence, then comparing the platform model before changing code. XH is the primary architectural reference. The XH checkout does not contain the complete VirtualApp runtime implementation, but its host manifest and documentation show the same platform shape: virtual package projection, broker/provider boundary, stub activities, process slots, and service routing. Legacy SX records are used as historical failure data, not copied as hooks.

## Historical hooks explicitly rejected

The old SX Quark JNI/native path redirects and BlackBox hooks were not moved into `GuestRuntime`, `ActivityLaunchCoordinator`, `PackageManager`, or the class-loader core. They were converted into generic path, ABI, lifecycle, and transport requirements and then tested at the platform boundary. No `com.quark.browser` condition or Tinker/Qigsaw condition is present in the product Core.

No E-class Quark compatibility patch is required by the current evidence; therefore there is no `WHY_NOT_GENERAL` exception beyond this record that the historical hook implementations are not the solution.
