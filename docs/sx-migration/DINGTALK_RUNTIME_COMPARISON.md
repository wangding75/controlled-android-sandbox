Target: stable login/privacy-policy/home entry; no account login required

The earlier `System.exit(0)` observation was not accepted as an App-private blocker. Decompilation shows that `LaunchHomeActivity` calls `ExportedActivityUtils.a(this)` before `super.onCreate`; the utility intentionally routes to `PrivacyPolicyActivity`, finishes the current Activity, logs `checkExportedActivityStartup and exit`, and exits the current Guest process. The Sandbox defect was losing the pending Activity route/task state during that process restart.

## WHY_NOT_GENERAL for an App patch

No App/SDK-specific compatibility patch was added. The observed `System.exit` is DingTalk’s own Activity handoff, but retaining/rebinding the pending Android Activity route is required for any Guest process recreation. XH’s container/stub model and the current r3 evidence support a generic Activity Runtime fix. The legacy DingTalk hook was therefore rejected rather than moved into Core or a package-specific bypass layer.
