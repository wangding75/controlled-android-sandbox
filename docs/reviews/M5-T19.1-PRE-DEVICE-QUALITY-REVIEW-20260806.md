## 2. 本轮关闭的问题

### 2.1 Guest 主线程与 Binder 重入

- Application、Service、Receiver、Provider 初始化和 JobService 生命周期统一进入 Guest 主线程调度器。
- 主线程发起同步 Broker 请求时允许安全处理同一 Guest 的回调，解除同步 Binder 环形等待。
- Guest 回调不再在持有全局组件锁的情况下跨越应用代码。
- 超时任务采用一次性认领，防止调用方超时后排队任务继续迟到执行。
- Job 启动使用 `starting` 预留集合，阻止同一 Job ID 并发重复回调。

### 2.2 ClassLoader 生命周期

- Activity 和非 Activity Guest 回调均在局部 Guest Thread Context ClassLoader 作用域执行。
- 所有作用域在 `finally` 中恢复原线程 ClassLoader，避免污染 Host 主线程或 Binder 线程池。

### 2.3 动态 Receiver 调度

- `registerReceiver(..., Handler scheduler, ...)` 保存真实调度 Handler。
- 动态 Receiver 在指定 Handler 上执行；未指定时使用 Guest 主线程。
- 调度路径支持与 Broker 同步回调重入，避免自定义 Handler 引入新的死锁。

### 2.4 Provider 权限与路径模型

Manifest、PackageState、typed contract、Broker 权限判定全链路新增或补齐：

- `readPermission`
- `writePermission`
- `grantUriPermissions`
- `<path-permission>`
- `<grant-uri-permission>`
- URI Grant 资格校验
- 读操作和写操作分别授权
- 每个 batch URI 独立校验
- 缺少权威 PackageState 时生产路径 fail-closed

### 2.5 Intent/Provider 路径匹配

- 移除把 Android `PATTERN_SIMPLE_GLOB` 错误等同于通用正则 `.*` 的实现。
- Provider 和 Receiver 使用独立的 Android simple-glob 匹配器。
- 增加路径 pattern 专项回归，避免 Resolver 与 Provider 权限规则产生不同解释。

### 2.6 代码质量与治理修复

- `RuntimeBrokerService` 保持在既有 1,300 行治理上限，没有扩大阈值。
- 新 Provider 元数据解析和权限判断拆分为独立职责类。
- `GuestContext`、Provider Registry 未跨越既有方法数量档位。
- 高复杂度方法档位低于冻结基线，没有新增复杂度债务。
- 清除本轮编译中的全部 `-Xlint:try` 警告。
- 新增 `check-pre-device-runtime-hardening.py`，并接入全量验证入口。
