## Purpose

Preserve the exact public source snapshots supplied by the project owner so later capability comparison does not depend on chat context or external repository availability. These trees are evidence/reference inputs, not Controlled Sandbox implementation source.

## Repository layout and backup contract

- Exact uploaded archives: `ref/archives/`
- Unmodified extracted trees: `ref/upstream/`
- Source, license, commit and tree hashes: `ref/manifests/`
- Internal development snapshots, Git bundles and complete backups include `ref/`.
- Product source releases generated by `scripts/package-release.sh` exclude `ref/`.
- Product APK/AAR/JNI builds never include `ref/` because no reference directory is registered in `settings.gradle`.

## Clean-room boundary

1. Reference source remains byte-preserved and read-only.
2. No reference Gradle wrapper, script or binary is executed by project tests.
3. Reviews may extract behavior, architecture, state transitions and compatibility test cases.
4. Product code must be independently designed and implemented against Android/AOSP contracts.
5. Direct copying, translation, mechanical rewriting or linking is prohibited.
6. VirtualApp source must not be publicly redistributed or used in product modules without separate rights review.

## Integrity verification

```bash
python3 tools/reference_sources.py verify
```

The gate verifies archive SHA-256, ZIP comment commit, safe archive paths, exact extracted file set, byte hashes, executable modes, license/notice paths, Git text-normalization protection, Gradle isolation and release-package exclusion.
